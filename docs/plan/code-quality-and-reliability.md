### 本次审查修正

1. **事件载荷**：按完整 JSON 消息的 UTF-8 字节数分批。单条超限事件在一个 SQLite 事务中归档到本机 `event_oversize` 表，并以同一序号的明确 `broken` 失败通知替换待发送项；原文在 ack 后仍保留，不跳过 seq、不伪造成功。兼容已有超限待发记录和重启重放。归档不自动清理，需纳入本地磁盘管理。
2. **HTTP 413**：超限后停止读取，但不在响应前销毁 socket；普通和 chunked 的真实 HTTP 连接均收到完整 413，而不是 `ECONNRESET`。
3. **浏览器隔离**：轮询证据替换为固定 waiting 响应；fixture 的 Node fetch 禁止外网与重定向逃逸，浏览器仅允许访问当前本地测试 origin。意外外网尝试即使被业务代码捕获，也使 teardown 失败。
4. **干净 checkout 的 CI 入口**：推送前检查发现远端 `e45cc39` 的 CI 已因 Node 24 job 缺少 `worker-configuration.d.ts` 失败（run `43743476425`）。`typecheck:node-host` 改为先执行 `wrangler types`，避免依赖开发机遗留生成文件；不放宽类型检查。

先红后绿证据：修复前新增的两个 connector 载荷用例失败（多字节批次越界；单帧 300,153 字节大于 262,144），两个真实 HTTP 用例失败（socket hang up）。修复后均通过。此前审查曾以拦截网络的方式复现 fixture 访问 GitHub 的路径；现由固定证据与守卫单测覆盖，未发送真实 GitHub 请求。

本地验证环境：Windows、Node `v24.19.0`、pnpm 使用根 `packageManager` 固定版本。全套 steward 在 Node 和 workerd 上各 **876 项通过**（68 个文件，三组并行，各约 234 秒）；全仓库及 Node 宿主类型检查通过；记忆 10 个案例、routing selftest 和 PR intent 34 项通过。浏览器使用 Playwright 固定版本的 Chromium Headless Shell，6 项通过，约 10 秒。

另外，connector 的 client/events/history-stream/heartbeat 共 44 项通过，包含真实限额 socket、重连、持久化重启与事务回滚；Node 宿主 HTTP/网络守卫 8 项通过。store 的其他 11 项通过，复跑时显式过滤了 POSIX `0600` 用例（1 skipped）；过滤结果不代表 store 全套通过。

上述本地复核的限制：当时未测远端 GitHub Actions 的运行耗时，未执行 Linux connector 全套；Windows store 测试中的 POSIX `0600` 断言及其清理 `EPERM` 属已记录的环境限制，未修改或掩盖该断言。浏览器失败截图/trace 已配置，但未通过故障注入验收其产物。上述本地复核没有付费模型调用或部署；后续提交、推送与 CI 检查单独记录。

- 单独提交，可以独立撤回。

不以拆到多少行为成功标准，不顺手大改 ledger 或 schema。

## 独立运维阶段：异地备份与恢复演练

需要服务器访问、存储选择和单独授权，不混进普通代码修改。

最近提交的验收记录仍注明异地备份未启用；计划制定时未连接服务器确认现状。仓库中有脚本，不代表部署已受保护。

### 工作内容

- [ ] 先只读确认线上是否已启用异地备份。
- [ ] 如未启用，确认存储位置、费用、保留周期及加密配置。
- [ ] 使用现有脚本上传数据库和必要恢复材料。
- [ ] 将解密配置保存在服务器之外。
- [ ] 检查恢复材料是否覆盖额外配置文件，明确哪些需要重新配置。
- [ ] 在隔离环境完成恢复演练：
  - SQLite 完整性检查。
  - 保存的密钥能够解开模型配置。
  - steward 能启动。
  - 测试 connector 能重新连接。

### 验收标准

以隔离环境恢复成功为准，而不是上传成功或校验和一致。不自动覆盖生产数据库或触发真实任务。

## 本轮不做

- 协议重写或替换为 Protocol Buffers / MessagePack。
- 自动备用模型切换。
- 向量记忆或 embedding 基础设施。
- 一次性把整个前端迁移到 TypeScript。
- 无实际故障依据地重做 Windows 启动方式或接入系统钥匙串。
- 为形式完整而优先建设 OpenAPI、复杂 i18n、完整 staging 或 CODEOWNERS。
- 为提高单次评测百分比反复调提示、选择性重跑或放宽标准。

## 交付与发布规则

每阶段交付：

1. 改动清单。
2. 修复前失败、修复后通过的证据；纯 CI 或重构阶段说明适用的验证方式。
3. 实际运行的测试及结果。
4. 未覆盖项、兼容性影响和回退方式。

执行边界：

- 本文是计划，不自动授权实施、push、部署或生产数据库操作。
- 不读取真实凭据，不调用付费模型。
- 不自动启动多代理；需要时由用户另行授权。
- 不覆盖已有工作区修改。
- 遇到范围外缺陷先记录，不顺手扩大修改。
- 各阶段独立验收，建议独立提交；是否提交、push 或部署依用户授权。

当前停止点：本轮已获授权审查、分批提交与推送并检查远端 CI；不部署、不推进独立运维阶段。授权仅限本轮，不构成未来自动发布权限。
