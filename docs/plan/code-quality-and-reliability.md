## 审查依据与已纠正的旧结论

前期报告包含未经核实的描述，不作为直接整改依据。基线代码核对结果：

- 当前使用 JSON WebSocket 文本帧，不是旧报告描述的自定义二进制 codec。
- 协议已有 `PROTOCOL_VERSION` 和握手版本兼容检查。
- 配对已有按 IP 和全局的失败锁定，不是完全没有暴力破解保护。
- 已有 steward 闭环、connector 实际传输和重启恢复测试；CI 不仅运行单元测试。
- connector 凭据存于 `connector.sqlite`，代码设置文件权限 `0600`；这不等于加密存储，也不证明 Windows ACL 已被加固。
- 预算已支持美元估算和 `DAILY_BUDGET_USD`，其软上限语义不应被当作缺陷改掉。
- 不采用旧报告的 routing 92%、memory 88% 数字。记忆评测是确定性信任边界检查，真实模型路由结果须绑定具体代码和运行配置。

- protocol：61 项测试通过。
- Node 侧选定测试：109 项通过，涵盖配对、握手、预算、路由审计、UI 模块、核心闭环、崩溃窗口和取消轮次。
- 记忆评测：10 个案例通过。
- PR intent 自测：34 项通过。
- routing selftest 通过。
- Node 宿主类型检查通过。

以上不是全仓库测试结果，也不是新的付费模型测量或生产验收。该次审查未修改项目文件、未连接生产服务器。

## 阶段 1：统一输入边界与排队保护

### 现状与涉及位置

工作台已有消息长度、请求体字节数、未完成用户轮次数量和请求 ID 冲突保护；Owner API 的 `POST /api/messages` 没有完整复用这些约束。Node 宿主还会在业务鉴权前完整读取请求体。

主要涉及：

- `apps/steward/src/steward.ts`
- `apps/steward/src/workspace-api.ts`
- `apps/steward/node-host/server.ts`
- `apps/connector/src/client.ts`
- 对应测试；必要时新增共享校验模块。

Owner API 已有认证，反向代理也可能限制请求体，因此这些发现不等于已证实的公网高危漏洞。目标是补齐应用自身的防御和入口一致性。

### 1.1 统一消息校验

- [ ] 工作台与 Owner API 复用核心消息约束。
- [ ] 消息必须是非空字符串，默认沿用现有 16,000 字符上限。
- [ ] 限制请求体字节数，区分字节与字符。
- [ ] 校验 ID、引用目标等字段。
- [ ] 正确拒绝 `null`、数组和错误字段类型等输入。

兼容性要求：

- 保留 Owner API 不传 ID 时自动生成 ID 的能力。
- 不要求 API 客户端采用只适用于浏览器的认证方式。
- 普通消息、设置等接口采用各自适当的体积限制，不粗暴共用一个值。

### 1.2 统一队列准入

- [ ] 把最多 10 个未完成用户轮次的保护放到共享准入路径。
- [ ] 工作台与 Owner API 合计受限，并发请求不能越过上限。
- [ ] 队列满返回 `429`，重复请求不占用新名额。
- [ ] 拒绝时不留下会导致重试被吞掉的持久化记录。
- [ ] 检查准入计数与持久化之间的并发、事务及崩溃窗口。
- [ ] 不妨碍停止轮次、查看花费等确定性操作。

### 1.3 明确幂等语义

- [ ] 相同 ID、相同内容只产生一次效果。
- [ ] 相同 ID、不同内容返回 `409`。
- [ ] 请求进行中或服务重启后重试，仍保持上述规则。
- [ ] 明确哪些字段构成同一请求，不只比较正文。

### 1.4 限制 Node HTTP 请求体

- [ ] 在读取过程中计数字节，超限立即终止，不先完整读入内存。
- [ ] 覆盖有或没有 `Content-Length`、分块传输及多字节字符。
- [ ] 覆盖读取中断、超限响应和连接清理。
- [ ] 未认证请求也受基础体积限制。

反向代理限制作为额外保护，不作为唯一保障。

### 1.5 明确 WebSocket 载荷边界

- [ ] 先盘点 hello、事件批次、历史记录等合法消息大小。
- [ ] 核对声明的 `maxMessageBytes` 与实际执行是否一致。
- [ ] 在 Node 服务端和 connector 接收端落实适当上限。
- [ ] 对超限及非法消息明确拒绝。
- [ ] 不截断合法消息，不破坏历史分块、重连及事件重放。

### 验收标准

- 新增回归测试通过。
- 工作台、Owner API、取消轮次、重启恢复、握手及历史读取相关测试通过。
- 不改变任务授权、worker 执行权限或模型预算策略。

## 阶段 2：修复记忆搜索漏词

### 现状与涉及位置

主要涉及：

- `apps/steward/src/notes.ts`
- `apps/steward/test/notes.test.ts`

已通过真实 migrations 和 notes 模块，在内存数据库复现：

| 查询 | 实际结果 |
| --- | --- |
| `登录` | 找到登录记录 |
| `部署` | 找到部署记录 |
| `登录 部署` | 只有登录记录 |
| `部署 登录` | 只有部署记录 |
| `nonexistent 登录` | 空结果，漏掉登录记录 |

原因：全部是短词时只搜索第一个；存在长词时只搜索长词，短词被忽略。与代码注明的多词 OR 召回不一致。

### 工作内容

- [ ] 保留现有多词 OR 召回语义。
- [ ] 长词继续走 FTS，短词通过转义后的 LIKE 参与召回。
- [ ] 合并候选并去重，统一应用仓库及层级范围。
- [ ] 保留当前版本优先、置顶和时间排序。
- [ ] 保留结果数量和字符预算。
- [ ] 检查查询词数量及候选规模，避免引入无界计算。

### 必测场景

- [ ] `登录 部署` 与 `部署 登录` 返回相同集合。
- [ ] `nonexistent 登录` 仍能找到登录记录。
- [ ] 多长词、多短词、混合词及重复词。
- [ ] `%`、`_`、引号等特殊字符。
- [ ] 仓库范围隔离、已移除记录排除。
- [ ] 历史版本顺序和结果预算。

### 验收标准

- 已复现的漏词问题消失。
- 现有 notes 测试和 10 个记忆评测案例全部通过。
- 不放宽记忆确认、来源或过期证据等信任边界。
- 不引入 embedding 或向量数据库。

## 阶段 4：建立浏览器冒烟测试

### 方案

优先采用 Playwright、本地真实 Node steward、脚本模型和隔离数据库。明确哪些组件是真实的、哪些是替身，不把局部测试包装成完整生产验收。

### 首批场景

- [ ] 登录、发消息、回复显示。
- [ ] 运行中停止轮次，界面正确收敛。
- [ ] PR 提案不立即生效，专用按钮确认后才生效。
- [ ] 普通回答或引用同意不能授权 PR 操作。
- [ ] 刷新、断线重连后恢复消息和状态，不重复执行。
- [ ] 过期或已处理卡片不能再次生效。

### 工程要求

- [ ] 独立测试目录和运行命令。
- [ ] 使用稳定定位方式，避免依赖布局细节。
- [ ] 失败时保存截图、trace 和必要日志。
- [ ] 自动清理进程、端口和临时数据库。
- [ ] 不接触真实 GitHub PR，不产生付费模型调用。

### 验收标准

- 在干净 CI 环境可以稳定执行。
- 能发现按钮失效、事件未绑定和刷新后状态错误等浏览器层问题。
- 稳定后接入 CI。

前端类型检查另行渐进推进，不与本阶段捆绑。

## 独立运维阶段：异地备份与恢复演练

需要服务器访问、存储选择和单独授权，不混进普通代码修改。

最近提交的验收记录仍注明异地备份未启用；计划制定时未连接服务器确认现状。仓库中有脚本，不代表部署已受保护。

### 工作内容

- [ ] 先只读确认线上是否已启用异地备份。
- [ ] 如未启用，确认存储位置、费用、保留周期及加密配置。
- [ ] 使用现有脚本上传数据库和必要恢复材料。
- [ ] 将解密配置保存在服务器之外。
- [ ] 检查恢复材料是否覆盖额外配置文件，明确哪些需要重新配置。
- [ ] 在隔离环境完成恢复演练：
  - SQLite 完整性检查。
  - 保存的密钥能够解开模型配置。
  - steward 能启动。
  - 测试 connector 能重新连接。

### 验收标准

以隔离环境恢复成功为准，而不是上传成功或校验和一致。不自动覆盖生产数据库或触发真实任务。

## 本轮不做

- 协议重写或替换为 Protocol Buffers / MessagePack。
- 自动备用模型切换。
- 向量记忆或 embedding 基础设施。
- 一次性把整个前端迁移到 TypeScript。
- 无实际故障依据地重做 Windows 启动方式或接入系统钥匙串。
- 为形式完整而优先建设 OpenAPI、复杂 i18n、完整 staging 或 CODEOWNERS。
- 为提高单次评测百分比反复调提示、选择性重跑或放宽标准。
